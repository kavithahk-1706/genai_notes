Q1. Explain the Transformer architecture in detail with a neat diagram. Describe the roles of the encoder and decoder stacks, and explain how they interact in encoder-decoder based models. 8M

Why Transformers?

Before Transformers, sequence models like RNNs and LSTMs processed tokens one at a time, which made training slow and made it hard to capture long-range dependencies. The Transformer, introduced in "Attention Is All You Need" (Vaswani et al., 2017), removes recurrence entirely and relies purely on the self-attention mechanism, allowing every token to attend to every other token in parallel.

Overall Architecture

The Transformer follows an encoder–decoder structure. The encoder maps an input sequence into a set of continuous representations; the decoder uses those representations, along with what it has generated so far, to produce the output sequence one token at a time.

Fig 1.1 — Transformer encoder–decoder architecture (Vaswani et al., 2017)

Role of the Encoder Stack

The encoder is a stack of N identical layers (N = 6 in the original paper). Each layer has two sub-layers:

  • Multi-Head Self-Attention: lets every input token look at every other input token and weigh how relevant each one is, producing a context-aware representation for each position.
  • Position-wise Feed-Forward Network: a two-layer fully connected network applied identically to each position, adding non-linearity and representational power.

Each sub-layer is wrapped with a residual connection followed by layer normalization — LayerNorm(x + Sublayer(x)) — which stabilizes training and lets gradients flow through deep stacks. Since attention has no notion of order, positional encodings (sinusoidal functions of position) are added to the input embeddings so the model knows token order.

The output of the encoder is a sequence of contextualized vectors, one per input token, that summarize the entire input in relation to every other token.

Role of the Decoder Stack

The decoder is also a stack of N identical layers, but each layer has three sub-layers:

  • Masked Multi-Head Self-Attention: attends only to earlier positions in the output sequence (future tokens are masked out), preserving the autoregressive property needed for generation.
  • Encoder-Decoder Cross-Attention: the queries come from the decoder, while the keys and values come from the encoder's output. This is exactly where the decoder "looks back" at the input sequence while generating each output token.
  • Feed-Forward Network: same role as in the encoder.

The final decoder output passes through a linear layer and a softmax to produce a probability distribution over the vocabulary for the next token.

How Encoder and Decoder Interact

  1. The encoder processes the full input sequence in parallel and produces a set of key-value pairs representing the input.
  2. The decoder generates output tokens one at a time (autoregressively). At each step, it first attends to the tokens it has already generated (masked self-attention).
  3. It then performs cross-attention against the encoder's output — this is the bridge that lets the decoder condition its generation on the full input sequence, not just what it has produced so far.
  4. This repeats layer by layer, and the final representation is converted into a probability distribution to pick the next token.
Key takeaway: The encoder builds a rich, bidirectional understanding of the input; the decoder generates output autoregressively while continuously consulting the encoder's representation through cross-attention. This division of labor is what makes encoder-decoder Transformers (like the original machine translation model, T5, and BART) effective at sequence-to-sequence tasks.

Q2. Explain various tokenization techniques used in Large Language Models such as Byte Pair Encoding (BPE), WordPiece, and SentencePiece. Illustrate the tokenization process with a suitable example. 8M

Why Tokenization Matters

LLMs cannot process raw text directly — text must be broken into discrete units called tokens, each mapped to an integer ID. The choice of tokenization strategy affects vocabulary size, how well the model handles rare/unseen words, and overall model efficiency. Modern LLMs use subword tokenization — a middle ground between word-level (huge vocabulary, can't handle unseen words) and character-level (small vocabulary, very long sequences).

1. Byte Pair Encoding (BPE)

BPE starts with a vocabulary of individual characters and iteratively merges the most frequent adjacent pair of symbols into a new symbol, repeating this a fixed number of times to build up a subword vocabulary. It is used in GPT-2/GPT-3.

Example: Given the word "lower" appearing frequently alongside "lowest" and "newer":

StepActionResult
0Start with charactersl · o · w · e · r
1Most frequent pair: (l, o)lo · w · e · r
2Most frequent pair: (lo, w)low · e · r
3Most frequent pair: (e, r)low · er

After enough merges, "low" and "er" become subword units reused across "lower", "lowest", and "newer", letting the model generalize to unseen combinations like "lowering" → low + er + ing.

2. WordPiece

WordPiece (used in BERT) is similar to BPE in that it also builds a vocabulary via merges, but instead of merging the most frequent pair, it merges the pair that maximizes the likelihood of the training data when added to the vocabulary — i.e. it picks merges that most improve the language model's probability of the corpus, not just raw frequency.

Example: The word "unhappiness" might be split as:

un + ##happi + ##ness

The ## prefix indicates the subword is a continuation of the previous token, not a new word — this lets WordPiece distinguish "happiness" from a token that happens to start with the same letters at the beginning of a word.

3. SentencePiece

SentencePiece is a tokenization framework (used by T5, LLaMA, ALBERT) rather than a single algorithm — it can implement BPE or a unigram language model internally. Its key innovation is that it treats the input as a raw stream of Unicode characters, including whitespace as a regular symbol (often represented as ▁), rather than assuming text is pre-split on spaces.

Example: The sentence "Hello world" tokenizes as:

▁Hello + ▁world

Because whitespace is encoded explicitly, SentencePiece is language-agnostic and works well for languages like Japanese, Telugu, or Chinese that don't use spaces to separate words — this is the main reason multilingual LLMs favor it over BPE/WordPiece.

Comparison

Common goal: All three balance vocabulary size against sequence length, and all handle out-of-vocabulary words gracefully by falling back to smaller subword units rather than an <UNK> token.

Q3. Explain the concept of embeddings and vector representations in NLP. Differentiate between static word embeddings and contextual embeddings, and discuss their role in semantic similarity tasks. 8M

What are Embeddings?

An embedding is a dense, low-dimensional vector representation of a discrete object (a word, subword, or token) such that objects with similar meaning end up close together in vector space. Instead of representing a word as a sparse one-hot vector of vocabulary size, embeddings compress meaning into a continuous space (typically 100–4000 dimensions), where geometric relationships (distance, direction) capture semantic relationships.

Static Word Embeddings

Static embeddings assign one fixed vector per word, regardless of context. Models like Word2Vec (CBOW / Skip-gram) and GloVe learn these vectors from co-occurrence statistics across a large corpus.

  • The word "bank" gets the exact same vector whether it means a riverbank or a financial institution.
  • Famous property: vector arithmetic captures analogies, e.g. vector("King") − vector("Man") + vector("Woman") ≈ vector("Queen").
  • Fast to use (a simple lookup table), but cannot disambiguate polysemous words.

Contextual Embeddings

Contextual embeddings, produced by models like ELMo, BERT, and GPT, generate a different vector for the same word depending on its surrounding context. The embedding is the output of running the full sentence through a deep neural network (typically a Transformer), so it reflects the word's role in that specific sentence.

  • "bank" in "I sat by the river bank" gets a different vector than "bank" in "I deposited money in the bank."
  • Captures syntax, polysemy, and long-range dependencies far better than static embeddings.
  • More computationally expensive — requires a forward pass through the model for every new context.

Role in Semantic Similarity Tasks

Once text is represented as vectors, semantic similarity between two pieces of text is typically measured using cosine similarity:

\[ \text{sim}(\vec{u}, \vec{v}) = \frac{\vec{u} \cdot \vec{v}}{\lVert \vec{u} \rVert \, \lVert \vec{v} \rVert} \]

A value close to 1 means the vectors point in nearly the same direction (highly similar meaning); close to 0 means unrelated; negative means opposite. This underlies applications such as:

  • Semantic search: retrieving documents whose embeddings are closest to a query embedding
  • Duplicate/paraphrase detection: flagging sentence pairs with very high cosine similarity
  • Clustering & recommendation: grouping similar items in embedding space
  • Retrieval-Augmented Generation (RAG): embedding a knowledge base and retrieving relevant chunks for an LLM's context
Key insight: Contextual embeddings from Transformer-based models are now the default for serious semantic-similarity work because a single static vector simply cannot represent a word that means different things in different sentences.

Q4. Discuss the applications of Large Language Models in text generation, summarization, translation, question answering, and conversational AI, with suitable examples for each. 8M

1. Text Generation

LLMs generate coherent, contextually relevant text by predicting the next token repeatedly, conditioned on everything generated so far.

Example: Given the prompt "Write a short poem about the monsoon," an LLM produces a fluent, stylistically appropriate poem — used in creative writing tools, marketing copy generation, and code generation (e.g. GitHub Copilot).

2. Summarization

LLMs condense long documents into shorter versions while preserving key information. This can be extractive (selecting important sentences) or abstractive (generating new sentences that paraphrase the content).

Example: Summarizing a 20-page research paper into a 200-word abstract, or condensing a news article into 3 bullet points — used in tools like news aggregators and legal document review.

3. Machine Translation

LLMs trained on multilingual data translate text between languages while preserving meaning, tone, and grammar, often outperforming older statistical machine translation systems because they capture context across the whole sentence rather than translating word by word.

Example: Translating "How are you?" into Telugu ("మీరు ఎలా ఉన్నారు?") while correctly handling grammatical gender and formality — used in tools like Google Translate (which now uses Transformer-based NMT) and real-time multilingual customer support.

4. Question Answering (QA)

LLMs answer natural-language questions either from their own trained knowledge (closed-book QA) or by reading a provided passage/document (open-book / reading-comprehension QA, often combined with retrieval).

Example: A student asks "What is the time complexity of merge sort?" and the model answers "O(n log n)" directly, or — given a textbook PDF — answers "According to Chapter 4, what causes thrashing in an OS?" by extracting the relevant explanation from the document.

5. Conversational AI

LLMs power multi-turn dialogue systems that maintain context across a conversation, adapt tone, and can call external tools — going beyond single-turn Q&A to sustained, coherent interaction.

Example: A chatbot that remembers earlier turns in a conversation ("earlier you said you're a second-year student — here's advice tailored to that"), used in customer support bots, virtual assistants (Siri, Alexa-style agents), and tutoring systems.

  • Clinical documentation: LLMs auto-generate doctor's notes from patient-doctor conversations, cutting administrative burden.
  • Diagnostic assistance: Generative models assist radiologists by drafting preliminary findings from medical images, later reviewed by a human.
  • Drug discovery: Generative models propose novel molecular structures with desired properties, accelerating early-stage research.

Impact: Reduces physician burnout from paperwork and speeds up early research timelines — but requires strict human-in-the-loop review given the high stakes of medical errors.

2. Education

  • Personalized tutoring: LLM-based tutors adapt explanations to a student's level and answer follow-up questions in real time.
  • Automated content generation: Generating practice questions, quizzes, and study notes tailored to a syllabus.
  • Accessibility: Real-time summarization and translation of lecture content for students with different needs.

Impact: Democratizes access to one-on-one style tutoring at scale, though it raises concerns about academic integrity and over-reliance on AI-generated answers.

  • Code generation and completion: Tools like GitHub Copilot suggest entire functions based on natural-language comments or partial code.
  • Automated testing: LLMs generate unit tests and identify edge cases from a function's signature and docstring.

Q6. Describe the architecture of Autoencoders and Variational Autoencoders (VAEs). Explain the role of the latent space and derive the Evidence Lower Bound (ELBO) loss function used in VAE training. 8M

Autoencoders — Basic Idea

An autoencoder is a neural network trained to reconstruct its own input. It consists of an encoder that compresses the input \(x\) into a low-dimensional latent representation \(z\), and a decoder that reconstructs \(x\) from \(z\). Training minimizes reconstruction error (e.g. mean squared error) between input and output.

Fig 6.1 — VAE architecture: encoder maps input to a latent distribution, decoder reconstructs from a sampled z

Standard Autoencoder vs Variational Autoencoder

A plain (vanilla) autoencoder maps each input to a single fixed point in latent space. This makes the latent space unstructured — there's no guarantee that points near each other decode to similar, meaningful outputs, and sampling a random point in latent space usually produces garbage. This makes vanilla autoencoders bad generative models.

A Variational Autoencoder (VAE) fixes this by making the encoder output a probability distribution over latent space — typically a Gaussian defined by a mean \(\mu\) and standard deviation \(\sigma\) — instead of a single point. During training, a latent vector \(z\) is sampled from this distribution using the reparameterization trick:

\[ z = \mu + \sigma \odot \epsilon, \quad \epsilon \sim \mathcal{N}(0, I) \]

This trick lets gradients flow through the sampling step (since the randomness is isolated in \(\epsilon\)), making the whole model trainable end-to-end via backpropagation.

Role of the Latent Space

VAE training additionally forces the latent distribution for every input to stay close to a standard normal prior \(p(z) = \mathcal{N}(0, I)\). This regularization makes the latent space smooth and continuous — nearby points decode to similar, realistic outputs, and random sampling from the prior produces coherent new data. This is exactly what makes VAEs usable as generative models: after training, you can generate new samples by simply drawing \(z \sim \mathcal{N}(0,I)\) and passing it through the decoder alone.

Deriving the ELBO

We want to maximize the likelihood of the data, \(\log p_\theta(x)\), but this requires integrating over all possible latent codes:

\[ p_\theta(x) = \int p_\theta(x|z)\, p(z)\, dz \]

This integral is intractable for complex decoders. So instead, we introduce an approximate posterior \(q_\phi(z|x)\) (the encoder) and rewrite the log-likelihood:

\[ \log p_\theta(x) = \mathbb{E}_{q_\phi(z|x)}\left[\log \frac{p_\theta(x,z)}{q_\phi(z|x)}\right] + D_{KL}\big(q_\phi(z|x)\,\|\,p_\theta(z|x)\big) \]

Since KL divergence is always \(\geq 0\), the first term is a lower bound on \(\log p_\theta(x)\) — this is the Evidence Lower Bound (ELBO):

\[ \log p_\theta(x) \geq \mathbb{E}_{q_\phi(z|x)}[\log p_\theta(x|z)] - D_{KL}\big(q_\phi(z|x)\,\|\,p(z)\big) = \text{ELBO} \]

Maximizing the ELBO (equivalently, minimizing its negative as a loss) is a tractable proxy for maximizing the true data likelihood. The ELBO decomposes into two interpretable terms:

  • Reconstruction term \(\mathbb{E}_{q_\phi(z|x)}[\log p_\theta(x|z)]\) — how well the decoder reconstructs \(x\) from a sampled \(z\); in practice this is implemented as MSE or binary cross-entropy loss.
  • KL regularization term \(D_{KL}(q_\phi(z|x)\,\|\,p(z))\) — penalizes the encoder's distribution for straying too far from the standard normal prior, keeping the latent space smooth.

The final VAE training objective (loss to minimize) is:

\[ \mathcal{L}_{VAE} = -\mathbb{E}_{q_\phi(z|x)}[\log p_\theta(x|z)] + D_{KL}\big(q_\phi(z|x)\,\|\,p(z)\big) \]
Key takeaway: The reconstruction term pushes the decoder to be accurate; the KL term pushes the latent space to be smooth and generative. The tension between the two is what gives VAEs their characteristic slightly-blurry-but-well-structured generations.

Q7. Explain the working principle of Generative Adversarial Networks (GANs). Describe the roles of the generator and discriminator, the minimax objective function, and the adversarial training process. 8M

Core Idea

A GAN consists of two neural networks trained simultaneously in an adversarial (competitive) game: a Generator (G) that tries to create fake data indistinguishable from real data, and a Discriminator (D) that tries to tell real data apart from the Generator's fakes. Neither network sees labeled "how to generate images" data — the entire learning signal comes from this competition.

Fig 7.1 — GAN architecture: Generator produces fakes from noise; Discriminator judges real vs fake; gradients flow back to improve both

Role of the Generator

The Generator \(G\) takes a random noise vector \(z\) (sampled from a simple prior like \(\mathcal{N}(0,I)\)) and maps it to a synthetic data sample \(G(z)\) — e.g. an image. Its goal is to make \(G(z)\) so realistic that the Discriminator cannot distinguish it from real data. It never sees real data directly; it only learns from the gradient signal passed back through the Discriminator.

Role of the Discriminator

The Discriminator \(D\) is a binary classifier that takes a sample (real or generated) and outputs the probability that it is real. It is trained on both real data (label = 1) and the Generator's fakes (label = 0), and its goal is to get as good as possible at telling them apart.

The Minimax Objective

The two networks play a two-player minimax game with value function \(V(D, G)\):

\[ \min_{G} \max_{D} V(D,G) = \mathbb{E}_{x \sim p_{data}(x)}[\log D(x)] + \mathbb{E}_{z \sim p_z(z)}[\log(1 - D(G(z)))] \]
  • D maximizes \(V\): it wants \(D(x) \to 1\) for real data and \(D(G(z)) \to 0\) for fake data — correctly classifying both.
  • G minimizes \(V\): it wants \(D(G(z)) \to 1\), i.e. it wants the Discriminator to be fooled into thinking its fakes are real.

At the theoretical equilibrium (Nash equilibrium) of this game, the Generator's distribution exactly matches the real data distribution, and the Discriminator can do no better than random guessing — \(D(x) = 0.5\) everywhere.

Adversarial Training Process

  1. Sample a batch of real data \(x\) and a batch of noise \(z\); generate fakes \(G(z)\).
  2. Train D: update the Discriminator's weights to maximize \(V(D,G)\) — improving its ability to separate real from fake (Generator weights frozen).
  3. Train G: update the Generator's weights to minimize \(\log(1 - D(G(z)))\) (or equivalently maximize \(\log D(G(z))\) for better gradients) — improving its ability to fool D (Discriminator weights frozen).
  4. Alternate steps 2 and 3 repeatedly. As training progresses, both networks improve together — the Generator produces increasingly realistic samples, and the Discriminator gets increasingly good at spotting subtle flaws, pushing the Generator further.
Practical challenges: GAN training is notoriously unstable — mode collapse (Generator produces limited variety), vanishing gradients (if D becomes too strong too fast, G gets no useful signal), and lack of a clear convergence metric are common issues addressed by techniques like Wasserstein GAN, gradient penalty, and careful learning-rate balancing.

Q8. Explain the working principles of Diffusion Models. Describe the forward (noise addition) and reverse (denoising) processes, and discuss how diffusion models generate high-quality samples. 8M

Core Idea

Diffusion models (e.g. DDPM — Denoising Diffusion Probabilistic Models) generate data by learning to reverse a gradual noising process. The intuition: it's easy to destroy an image by slowly adding noise until it becomes pure static; a diffusion model learns to run this process backward — starting from pure noise and gradually removing it, step by step, until a realistic sample emerges.

Fig 8.1 — Forward diffusion gradually adds noise; the reverse process, learned by a neural network, removes it step by step to generate new samples

Forward Process (Noise Addition)

The forward process is a fixed (not learned) Markov chain that gradually adds small amounts of Gaussian noise to a data sample \(x_0\) over \(T\) timesteps, until \(x_T\) is (approximately) pure noise:

\[ q(x_t \mid x_{t-1}) = \mathcal{N}\big(x_t;\ \sqrt{1-\beta_t}\,x_{t-1},\ \beta_t I\big) \]

Here \(\beta_t\) is a small variance added at step \(t\), following a fixed schedule. A convenient property of Gaussian noising is that we can jump directly from \(x_0\) to any noisy step \(x_t\) in closed form, without simulating every intermediate step:

\[ q(x_t \mid x_0) = \mathcal{N}\big(x_t;\ \sqrt{\bar\alpha_t}\,x_0,\ (1-\bar\alpha_t) I\big), \quad \bar\alpha_t = \prod_{s=1}^{t}(1-\beta_s) \]

Reverse Process (Denoising)

The reverse process is what the model actually learns. It is also modeled as a Markov chain, but each step now attempts to remove a small amount of noise:

\[ p_\theta(x_{t-1} \mid x_t) = \mathcal{N}\big(x_{t-1};\ \mu_\theta(x_t, t),\ \Sigma_\theta(x_t, t)\big) \]

In practice, a neural network (typically a U-Net) is trained to predict the noise \(\epsilon\) that was added at step \(t\), given the noisy input \(x_t\) and the timestep \(t\). The training loss is simply the mean squared error between the true noise and the predicted noise:

\[ \mathcal{L} = \mathbb{E}_{x_0,\, \epsilon,\, t}\Big[\ \lVert \epsilon - \epsilon_\theta(x_t, t) \rVert^2\ \Big] \]

Once trained, generation starts by sampling pure noise \(x_T \sim \mathcal{N}(0, I)\) and repeatedly applying the learned reverse step for \(t = T, T-1, \dots, 1\), gradually refining the noise into a coherent sample \(x_0\).

Why Diffusion Models Produce High-Quality Samples

  • Gradual refinement: Breaking generation into many small denoising steps is an easier learning problem than generating an entire realistic sample in one shot (as GANs attempt), leading to sharper, more diverse outputs.
  • Stable training: Unlike GANs, there is no adversarial game — training is a straightforward regression (predict the noise), which avoids mode collapse and training instability.
  • Better mode coverage: Diffusion models tend to cover the full diversity of the training distribution rather than collapsing onto a few common modes.
  • Guidance mechanisms: Techniques like classifier-free guidance let the reverse process be conditioned on text prompts, enabling controllable, high-fidelity generation (as in DALL·E 2, Stable Diffusion, Midjourney).
Trade-off: The main cost of this quality is inference speed — generating a sample requires many sequential denoising steps (often 20–1000), making diffusion models slower at inference than a single forward pass through a GAN generator. Techniques like DDIM sampling reduce the number of steps needed.

Q9. Explain data augmentation techniques using generative models. Discuss how these techniques improve the performance and robustness of downstream machine learning models. 8M

What is Generative Data Augmentation?

Traditional data augmentation applies simple transformations (rotation, cropping, flipping for images; synonym replacement for text) to existing data. Generative data augmentation goes further — it uses generative models (GANs, VAEs, diffusion models, or LLMs) to synthesize entirely new, realistic training examples rather than just perturbing existing ones, especially useful when real data is scarce, imbalanced, or expensive to collect/label.

Key Techniques

  • GAN-based augmentation: A GAN is trained on the existing (often minority-class) dataset, then used to generate additional synthetic samples of that class. Widely used in medical imaging, where diseased-tissue samples are rare compared to healthy ones.
  • VAE-based augmentation: Because the VAE latent space is smooth, new samples can be created by interpolating between two real examples in latent space, or by sampling nearby points around a real example's latent code — producing plausible variations.
  • Diffusion-based augmentation: A diffusion model trained on the target domain generates diverse, high-fidelity synthetic samples, often producing higher quality and more diversity than GAN-based approaches.
  • LLM-based text augmentation: An LLM paraphrases existing sentences, generates new examples in a given style, or produces synthetic labeled examples for low-resource NLP tasks (e.g. generating more examples of a rare intent class for a chatbot).
  • Conditional generation for class balancing: Class-conditional GANs/diffusion models can be specifically prompted to generate more examples of underrepresented classes, directly addressing class imbalance.

How This Improves Downstream Models

BenefitExplanation
Addresses class imbalanceSynthetic minority-class samples reduce bias toward the majority class, improving recall on rare classes
Improves generalizationMore diverse training data reduces overfitting to the limited patterns present in a small real dataset
Increases robustnessExposure to a wider variety of synthetic variations makes models more resilient to distribution shift and edge cases at test time
Reduces data collection costSynthetic data reduces reliance on expensive/slow real-world data collection and manual labeling
Preserves privacySynthetic samples can replace sensitive real data (e.g. patient records) during model development
Caution: Poor-quality or unrealistic synthetic data can introduce artifacts or biases of its own into the downstream model — synthetic data quality should always be validated (e.g. via FID score for images, or human evaluation) before being trusted for training.

Q10. Discuss the concept of privacy-preserving synthetic data generation. Explain how generative models can be designed to protect sensitive information while preserving statistical utility of the data. 8M

Why Privacy-Preserving Synthetic Data?

Many high-value datasets — medical records, financial transactions, personal user data — cannot be shared or used freely due to privacy regulations (HIPAA, GDPR) or ethical concerns. Privacy-preserving synthetic data generation uses generative models to create artificial datasets that statistically resemble the real data (preserving distributions, correlations, and patterns useful for analysis or model training) without containing any real individual's actual record.

Core Techniques

1. Differential Privacy (DP)

Differential privacy provides a mathematical guarantee that the presence or absence of any single individual's data in the training set has a negligible, bounded effect on the model's output. This is achieved by adding calibrated noise during training.

  • DP-SGD (Differentially Private Stochastic Gradient Descent): clips per-example gradients and adds Gaussian noise to them before updating model weights, bounding how much any single data point can influence the trained generative model.
  • The privacy guarantee is quantified by a parameter \(\varepsilon\) (epsilon) — smaller \(\varepsilon\) means stronger privacy but typically lower data utility, representing a fundamental privacy-utility trade-off.

2. DP-GANs

A GAN whose Discriminator is trained using DP-SGD. Since the Generator only ever learns through gradients passed back from the Discriminator, making the Discriminator differentially private effectively makes the entire generation pipeline private — the Generator never gets a strong enough signal to memorize and reproduce any individual real record.

3. Federated Generative Modeling

The generative model is trained across multiple decentralized data sources (e.g. different hospitals) without the raw data ever leaving its original location — only model updates (gradients) are shared and aggregated centrally, combined with DP noise for additional protection.

4. Membership Inference Defense

Generative models are specifically evaluated against membership inference attacks (attempts to determine whether a specific real record was in the training set) to ensure the synthetic data generator hasn't simply memorized and can reproduce training examples.

Preserving Statistical Utility

The goal is not just privacy but also usefulness — synthetic data must preserve enough statistical structure (marginal distributions, correlations between features, class balance) that models trained on it perform comparably to models trained on the real data. This is validated using:

  • Utility metrics: training a downstream classifier on synthetic data and testing on real held-out data (Train-Synthetic-Test-Real, TSTR)
  • Statistical similarity tests: comparing distributions of the real vs synthetic data (e.g. KS-test on individual features, correlation matrix comparison)
  • Fidelity scores: such as FID for images, or custom domain-specific metrics for tabular/medical data
Key insight: Privacy-preserving synthetic data generation is fundamentally a balancing act — the \(\varepsilon\) in differential privacy and the noise added during training directly trade off against data utility. Practitioners must choose an operating point appropriate to the sensitivity of the data and the intended downstream use.

Q11. Explain Chain-of-Thought (CoT) reasoning in Large Language Models. Demonstrate, with an example, how CoT prompting improves performance on multi-step reasoning tasks. 8M

What is Chain-of-Thought Reasoning?

Chain-of-Thought (CoT) prompting is a technique where an LLM is prompted (either through instruction or via few-shot examples) to generate intermediate reasoning steps before producing a final answer, instead of jumping straight to the answer. Rather than mapping the question directly to the answer, the model is guided to "think out loud," breaking a complex problem into a sequence of smaller, simpler sub-steps — similar to how a student shows their working on a math exam rather than writing only the final number.

Why It Works

  • LLMs generate text autoregressively — each token is conditioned on everything generated before it. By first generating reasoning steps, the model conditions its final answer on its own intermediate deductions, which sharply reduces errors on tasks that require multiple logical or arithmetic steps.
  • Without CoT, the model must implicitly perform all reasoning "in one shot" within a single forward pass to the answer token — which fails on anything beyond fairly simple problems.
  • CoT emerges as a capability mainly in sufficiently large models — it is considered an emergent ability that appears once model scale crosses a certain threshold.

Example — Standard Prompting vs CoT Prompting

Problem: "Roger has 5 tennis balls. He buys 2 more cans of tennis balls. Each can has 3 tennis balls. How many tennis balls does he have now?"

Standard prompting (direct answer):
Q: Roger has 5 tennis balls. He buys 2 more cans of tennis balls. Each can has 3 tennis balls. How many does he have now?
A: 11

Without shown reasoning, the model has a much higher chance of making an arithmetic slip on multi-step problems, especially as the number of steps grows.

Chain-of-Thought prompting:
Q: Roger has 5 tennis balls. He buys 2 more cans of tennis balls. Each can has 3 tennis balls. How many does he have now?
A: Roger started with 5 balls. 2 cans of 3 tennis balls each is 2 × 3 = 6 tennis balls. 5 + 6 = 11. The answer is 11.

By explicitly writing out "2 cans × 3 balls = 6" and then "5 + 6 = 11" as separate steps, the model is far less likely to skip or miscombine a step — each intermediate result is grounded in the text before the final answer is produced.

Where CoT Helps Most

Task TypeExample
Arithmetic reasoningMulti-step word problems (as above)
Commonsense reasoning"If it's raining and John forgot his umbrella, what should he do?"
Symbolic reasoningTracking state across a sequence of operations (e.g. last-letter concatenation)
Multi-hop question answeringQuestions requiring combining facts from multiple sources

Prompting Variants

  • Few-shot CoT: the prompt includes a few worked examples showing step-by-step reasoning before the actual question.
  • Zero-shot CoT: simply appending a phrase like "Let's think step by step" to the prompt, without any worked examples, has been shown to reliably trigger step-by-step reasoning in large models.
Key takeaway: CoT doesn't add any new knowledge to the model — it restructures how the model uses its existing knowledge, giving it "room to think" across multiple generation steps instead of forcing a single leap to the answer.

Q12. Explain the concept of self-consistency prompting. Describe how it can be combined with Chain-of-Thought reasoning to improve the reliability of LLM outputs. 8M

The Problem with a Single CoT Path

Even with Chain-of-Thought prompting, an LLM generates text via sampling — a single reasoning path can go wrong at any step (a slip in arithmetic, a wrong logical branch), and that one flawed path is all a standard CoT approach relies on to reach its final answer. There's no way to check the answer against alternative ways of solving the same problem.

What is Self-Consistency?

Self-consistency is a decoding strategy that addresses this by generating multiple independent reasoning paths for the same question (by sampling with temperature > 0 rather than always taking the single most likely path), extracting the final answer from each path, and then selecting the answer that occurs most frequently across all the sampled paths — essentially a majority vote over diverse chains of thought.

Fig 12.1 — Self-consistency: sample several CoT reasoning paths for the same question, then take a majority vote over their final answers

How It Combines with Chain-of-Thought

  1. Prompt with CoT: Use a CoT prompt (few-shot or "let's think step by step") so the model produces explicit reasoning steps, not just a direct answer.
  2. Sample multiple times: Instead of greedy decoding (always picking the highest-probability next token), sample the model's output several times (e.g. 10–40 times) with a non-zero temperature, so each run can take a genuinely different reasoning path.
  3. Extract final answers: Parse out just the final answer from each of the generated reasoning chains, discarding the reasoning text itself at this stage.
  4. Marginalize via majority vote: Select the answer that appears most often across all sampled paths as the final output. Paths that reach the same correct answer via different routes reinforce each other, while a single flawed path gets outvoted.

Why This Improves Reliability

  • Error cancellation: If a mistake in one reasoning path is essentially "random noise," it's unlikely that the same mistake recurs identically across many independently sampled paths — so the correct, more common answer dominates the vote.
  • Captures problem diversity: Many reasoning problems can be solved via multiple valid approaches; sampling diverse paths mirrors how a human might double-check an answer using a different method.
  • No extra training required: Self-consistency is purely a decoding-time strategy — it requires no fine-tuning, just multiple forward passes at inference time.
  • Confidence signal: The proportion of paths agreeing on the majority answer can itself be used as a rough confidence estimate for the final output.
Trade-off: Self-consistency multiplies inference cost by the number of sampled paths (e.g. 20–40× more generation calls), so it's typically reserved for cases where correctness matters more than latency or cost — such as exam-style reasoning benchmarks or high-stakes decision support, rather than every everyday chatbot query.
